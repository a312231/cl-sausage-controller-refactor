# 故障停热与下平台半故障加固设计

## 目标

在不改变低/高并发烤肠调度、25~33 整批成熟和整批回搬策略的前提下，修复故障停热并发覆盖、暂停补偿掉电不一致、冷启动顺序和半故障重启升级维护问题。

## 方案

1. 所有 503/504/505 温控写入统一经过 `faultHeatTransitionLock`。故障暂停期间拒绝正温写入，但允许写 0；半故障状态不参与该门控。
2. 故障补偿使用可重放 journal，保存暂停段、绝对 `startTime` 目标和待丢弃盘。journal、烤盘和配置均使用同步持久化；重启按绝对值重放，禁止重复累加。
3. 冷启动先处理断电缺口，再执行营业时间纠偏和温控恢复。
4. 动作组恢复仅对与持久化 `ISOLATED` episode 完全匹配的安全补肠终态降级处理；升降台危险码、未知码、RUNNING、无匹配 session 仍进入维护。

## 不变量

- 故障暂停活动时，任何正常算法路径不能把 503/504/505 写成正温。
- journal 未安全完成前保持暂停和停热。
- 半故障不修改 `onlineStatus`、`errorStatus`、`isEnable`，不阻断上平台售卖、加热和上平台搬运。
- 低/高并发调度核心文件和 25~33 批次规则保持行为不变。

## 验证

覆盖温控交错写入、暂停期间正温拒绝、journal 各掉电阶段重放、冷启动顺序、半故障恢复匹配和原有全量测试；真实 RS485、断电和 MQTT 联调仍需现场验证。
